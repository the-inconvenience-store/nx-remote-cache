# Domain docs

## Layout and reading rules

This repository is single-context:
- Vocabulary: `GLOSSARY.md` at the repository root.
- Architecture decisions: `docs/adr/`.

Before exploring a domain area, read the glossary and relevant ADRs.
If either is absent, proceed silently. Create domain documents lazily through
the domain-modeling skill when terminology or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
Reconsider an unfamiliar term before recording a genuine vocabulary gap.

## Decision conflicts

Explicitly identify any proposal that contradicts an existing ADR, including
the ADR identifier and the reason to reopen the decision.
